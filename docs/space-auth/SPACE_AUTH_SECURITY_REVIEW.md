# SPACE_AUTH_SECURITY_REVIEW

> 地球online · 身份/空间/备份 安全评审
> 方法：以现有代码为攻击面（Worker 856 行、前端 16 个 JS），逐条给出「风险 → 条件 → 影响 → 防护 → 是否需额外基础设施」。
> 结论分级：**严重**（可导致他人数据泄露或丢失）/ **高** / **中** / **低**。
> **模型：两态（`guest` / `user`）**。`legacy` 只指旧版数据库/旧版存储/历史函数名，不是空间（设计 §1.6）。

## T1 用户 A 访问用户 B 的备份

- **发生条件**：客户端能提交 `spaceKey` / `objectKey` / `writeId` 并让服务端照做。
- **现状风险**：`handleV2ObjectPut` 直接采信 body 里的 `im.objectKey`（`index.js:573,595`）；所有 key 是常量（`:27-32`）——**当前是单租户，所以"访问别人"等于"访问唯一那份"**。
- **影响**：读到/覆盖他人完整业务数据。
- **防护**：
  1. 服务端从会话推 `spaceKey`，**只**用 `prefixOf(spaceKey)` 拼 key（设计 §5.2）。
  2. `im.objectKey` 必须严格等于 `prefix + 'objects/' + writeId + '.json'`，否则 400。
  3. `pointer.objectKey` 同规则；`pointer.writeId` 与 object metadata 必须一致（已有 `:688`）。
  4. 新增 GET object 时同样只从派生 key 读。
  5. 交叉测试：A 的 token + B 的 writeId → 必须 400/404（Phase E 验收项）。
- **额外基础设施**：无。

## T2 伪造 userId 越权

- **发生条件**：API 接受 `?userId=` / body `userId` / 自定义 header 作为身份。
- **影响**：同上，且比 T1 更隐蔽（正确签名但身份错）。
- **防护**：
  1. **任何**业务接口不接受客户端身份参数；`ctx.user` 只来自 D1 `sessions`。
  2. 路由层统一注入，handler 内部不得再读 `request` 里的身份字段（代码评审项）。
  3. 若未来加管理端，管理端与用户端用**不同 cookie 名**，管理端另做 IP 白名单。
- **额外基础设施**：无。

## T3 会话被盗 / 重放

- **发生条件**：XSS 读出 token；HTTP 明文传输；日志打印 Cookie。
- **影响**：完全冒充用户（读备份、改 pointer、注销账号）。
- **防护**：
  1. HttpOnly 阻止 JS 读取；Secure 强制 HTTPS。
  2. 服务端只存 `token_hash`（SHA-256）。
  3. 滑动 30 天 + 绝对 90 天上限；敏感操作要求 5 分钟内重新验证。
  4. 换绑邮箱/删除账号 → 吊销其它设备。
  5. 日志只记录 `sessions.id` 前 6 位（沿用 `logLine` 策略 `index.js:49-54`）。
  6. 前端禁止 `document.cookie` 读取；CSP 限制内联脚本（Phase H）。
- **重放**：Cookie 天然随请求重放，靠 `SameSite` + Origin 限制来源；写操作全部走 POST/PUT + JSON Content-Type。
- **额外基础设施**：可选 Cloudflare Turnstile。

## T4 验证码暴力破解

- **发生条件**：6 位码 + 无限尝试。
- **影响**：任意邮箱登录。
- **防护**：
  1. 单码 5 次尝试后作废（`attempts` 列）。
  2. 同邮箱 5 次/小时；同 IP 20 次/小时。
  3. 6 位随机来自 `crypto.getRandomValues` + 拒绝采样。
  4. 失败响应统一 `code-invalid`，不区分分支。
  5. 监控：单 IP 失败率突增 → 告警。
- **额外基础设施**：D1 计数表；可选 WAF 速率规则。

## T5 邮箱枚举

- **发生条件**：`/api/auth/code` 对存在/不存在邮箱返回不同状态或不同耗时。
- **影响**：泄露「某人是否注册」。
- **防护**：
  1. 统一 `202 {ok:true,resendAfter}`。
  2. 不存在邮箱时**也**走一遍「生成码 → 丢弃」的等长路径。
  3. 冷却与限流对两种情况一致。
  4. 供应商错误不回传给客户端。
- **额外基础设施**：无。

## T6 验证码重复使用

- **发生条件**：验证成功后未标记消费；或并发两个请求同时通过校验。
- **影响**：一次泄露的码可多次登录。
- **防护**：
  1. 校验与消费在同一条 SQL：`UPDATE email_codes SET consumed_at=? WHERE id=? AND consumed_at IS NULL`，用 `meta.changes === 1` 判定。
  2. 建会话放在同一事务之后；失败则码已消费需重发。
- **额外基础设施**：无。

## T7 邮件发送滥用

- **发生条件**：脚本批量请求 `/api/auth/code`。
- **影响**：发信额度耗尽、域名信誉受损。
- **防护**：
  1. 三层限流：IP / 邮箱 / 全局。
  2. 60 秒冷却 + 每日每邮箱上限（如 10 封）。
  3. Cloudflare Rate Limiting 规则。
  4. 可选 Turnstile。
  5. 邮件正文不含用户可控内容。
  6. SPF/DKIM/DMARC 配齐；退信率监控。
- **额外基础设施**：**是** —— Cloudflare Rate Limiting 或 Turnstile。

## T8 CORS / CSRF

- **发生条件**：任意站点用用户浏览器发起跨站写请求。
- **现状**：已有 CORS 单源白名单（`index.js:56-70`）+ Origin 检查（`:791-794`）。
- **防护**：
  1. 保留 Origin 白名单，不回显任意来源。
  2. `SameSite=Lax`：跨站 POST 不带 cookie。
  3. 写操作要求 `Content-Type: application/json` + 二次校验 `Origin`。
  4. 关键操作要求显式确认字段。
- **额外基础设施**：无。

## T9 Cookie 安全属性

- **防护**：
  1. 同源部署时用 `__Host-eo_sess`（强制 Path=/、Secure、无 Domain）。
  2. `HttpOnly` + `Secure` + `SameSite=Lax`。
  3. `Path=/`，不留 `Domain`。
  4. 测试断言原始 `Set-Cookie` 头。
  5. 不使用 `SameSite=None`。
- **额外基础设施**：无。

## T10 R2 凭证泄露

- **现状**：Worker 只用 binding（`index.js:346-351`），前端只带 cookie（`cloud-backup.js:140`），桶私有（`wrangler.toml:22-25`）。
- **防护**：
  1. 保持「浏览器永不接触 R2 凭证」。
  2. 不引入 S3 临时凭证给浏览器（`r2-s3-integration.cjs` 是测试工具）。
  3. 桶保持私有、无公开链接。
  4. `wrangler.toml` 不含 secret。
- **额外基础设施**：无。

## T11 游客空间误上传

- **发生条件**：游客态下 `markDirty` 仍触发上传；或迁移前误把游客库当用户库上传。
- **现状**：已有四道门禁（`cloud-backup.js:21-25,177,196,207,216`），但**只在前端**。
- **防护**：
  1. 前端门禁保留（第一层），并在两态模型下改为「`identity.space !== 'user'` 一律不上传」。
  2. **服务端兜底**：`/api/backup/*` 必须带有效会话；游客没有会话 → 401。
  3. 迁移期间上传的目标是**用户库**（`-u-` 前缀）；上传函数只接受 `space='user'` 的数据源。
  4. 测试：游客态手动调 `OLCloudBackup.backupNow()` → 返回 false 且无网络请求。
  5. **例外边界**：「补撤销上次退出」（设计 §3.4.1）是 guest 态唯一的 `/api/*` 调用，只发 `POST /api/auth/logout`，不读写任何备份数据；必须有专门测试断言它不会夹带 payload。
- **额外基础设施**：无。

## T12 退出后旧 Session 仍有效

- **发生条件**：退出只清 cookie，不删服务端记录；或 token 被复制到别处。
- **影响**：退出形同虚设。
- **防护**：
  1. 退出 = `UPDATE sessions SET revoked_at=?` + 清 cookie（**服务端为准**）。
  2. 中间件每次校验 `revoked_at IS NULL AND expires_at > now`。
  3. 提供 `logout-all`；改邮箱/注销自动吊销其它会话。
  4. 吊销后旧 cookie 访问 → 401。
  5. **客户端不得假定成功**：`revoked` / `failed` / `offline` 三态分开处理（设计 §3.4、T20）。
- **额外基础设施**：无。

## T13 多标签页空间串用

- **发生条件**：一个标签页已连 A 库，另一个标签页把 identity 改成 B（登录/退出），第一个标签页继续写。
- **影响**：数据写进错误的空间。
- **防护**：
  1. 库连接在启动时固定；identity 变化通过 `storage` 事件广播。
  2. 收到变化且 `dbName` 不同 → **立即置只读** + 提示刷新，不自动 reload。
  3. 写入租约 per-DB，跨库不互相阻塞，靠只读降级兜住。
  4. 测试：两标签页模拟 → 旧标签页写操作被拒。
- **额外基础设施**：无。

## T14 恢复操作覆盖本地数据

- **防护**：
  1. 永不自动恢复；只在新设备（空库）或用户显式确认后执行。
  2. 判定表（设计 §6.2）区分「云端更新 / 本地更新 / 双向分叉」。
  3. 两阶段：暂存库 → 校验 → 快照 → 替换 → 校验。
  4. 保留 `-bak-<ts>` 24 小时 + 「撤销这次恢复」。
  5. 前后都要求 `payloadHash` 一致。
  6. **再次登录时本地优先**：本机已有数据 → 不弹恢复面板，只在卡片提示（设计 §3.5）。
- **额外基础设施**：无。

## T15 迁移过程中数据丢失

- **发生条件**：移动而非复制；云端未成功就删源；半迁移库被当正常库用。
- **影响**：游客数据永久丢失。
- **防护**：
  1. **复制**语义，源库只读、永不删除（设计 §3.6 规则 1）。
  2. 提交点是写 identity，且必须 `stage=uploaded` 之后（决策 C 第 7 条）。
  3. 目标库带 `meta.import.id`，半迁移可识别、可清理。
  4. 全流程状态机落盘，重启可继续/放弃。
  5. 迁移完成前禁止任何「清空游客数据」入口（UI 置灰）。
  6. **源库恒为 guest**：不存在从第三种空间迁移的路径；`from` 字段只允许 `'guest'`。
- **额外基础设施**：无。

## T16 R2 Pointer 被错误更新

- **防护**：
  1. 保留全部现有校验（revision +1、etag 强匹配、pointer→object 哈希一致、immutableJson 一致）。
  2. pointer key 必须由 `spaceKey` 派生；`pointer.objectKey` 必须以同前缀开头。
  3. 条件写失败一律 409，不重试（现状 `:729-736`）。
  4. 测试：并发两个 PUT，仅一个成功；revision 跳跃被拒。
- **额外基础设施**：无。

## T17 旧数据被误判为空库

> 新增于 2026-11-26；两态收敛后重写（原「fail-safe 到 legacy」不再成立）。

- **风险**：升级后应用把「有数据的旧库」判成空库，直接新建空游客空间，用户看到的是演示数据，以为记录全没了（数据其实还在 `earthonline` 库里，但没有任何入口）。
- **发生条件**：
  1. 判定只看 `localStorage['earthonline-v4-migrated']`——用户清过 localStorage 但 IndexedDB 还在 → 标记消失 → 判空。
  2. 反方向：清过 IndexedDB 但 localStorage 还在 → 标记还在 → 误判为「已迁移完成」→ 空库。
  3. `indexedDB.open` 被其它标签页 `versionchange` 卡住 → promise 永远 pending → 无超时则挂死；catch 后判空 → 误判。
  4. 打开库时用了 `onupgradeneeded` 逻辑，把「库不存在」与「库为空」混为一谈。
  5. **两态模型特有**：把 `unknown` 当作「可以安全新建空游客空间」——这是最危险的一种，因为它会写下一份看似正常、实则掩盖旧数据的身份记录。
- **影响**：**严重**。不是数据损坏，是「数据不可达」——用户极可能直接卸载/清缓存，把可恢复变成不可恢复。
- **防护**（设计 §3.2）：
  1. 三步独立取证：库内容（强）→ `earthonline-v4`（弱）→ 异常（不可用）。
  2. **`earthonline-v4-migrated` 不参与空间判定**，只留给 `OLMigrate.status()` 做迁移判定。
  3. **`unknown` 一律阻断**：不写 identity、不建库、不开库、不显示「游客空间」。阻断页只给「重试」（+ 可选的兼容模式），**不给「跳过并开始使用」**。
  4. 探测带 1500ms 超时，超时不等于空。
  5. 结论写 `detectedBy`（`rows` / `localStorage` / `none`），线上可追溯走了哪一支；`unknown` 不写记录，用诊断日志留痕。
  6. 认领路径常显「升级前的记录都在」文案，给用户兜底认知。
  7. 记录损坏且本机存在 `earthonline-u-*` 库 → 阻断并引导登录（设计 §3.2.3 第 7 条），不得静默新建游客空间。
- **额外基础设施**：无。

## T18 旧数据探测自身造成副作用或启动阻塞

- **风险**：为了判断「有没有旧库」而打开数据库，反而改动了数据或拖慢启动。
- **发生条件**：
  1. `indexedDB.open('earthonline')` **不带版本且库不存在时会创建空库**。
  2. 探测里调用了 `OLMigrate.status()/run()` 或写了 `meta`。
  3. 探测里带版本号 open → 与其它标签页冲突 → `blocked`，启动永久挂起。
  4. 探测无超时 → 隐私模式/被禁用存储时长时间 pending → 白屏。
- **影响**：中。最坏是启动挂死，或产生一个无害空库。
- **防护**：
  1. 先 `indexedDB.databases()` 判断存在性（支持的浏览器），不支持才 open。
  2. open **不带版本**（同版本连通、不触发 `upgradeneeded`）。
  3. 探测**只读**：只 `count()` / `get()`，不 `put`、不删库、不调 `OLMigrate`、不读写 `earthonline-v4`。
  4. 1500ms 超时 → `unknown` → 阻断页。
  5. 探测只在 identity 记录缺失/损坏时执行一次。
  6. 阻断页给出 `reason`（`detect-timeout` / `db-blocked`），便于区分「慢」与「坏」。
- **额外基础设施**：无。

## T19 游客数据被自动并入用户空间 / 迁移被自动触发

> 新增（编号复用自原「切换后旧连接仍写旧库」，该项随决策 F 撤销）。对应决策 C 第 4/5 条、决策 E 第 6 条。

- **风险**：登录成功后，客户端「顺手」把游客库数据带进 user 空间；或把「进入用户空间」与「迁移数据」合成一步，用户没点确认就发生了复制。
- **发生条件**：
  1. 登录流程把 `plan()/run()` 放在询问之前；
  2. 本机已有 user 库时仍执行「迁移」，变成未设计的合并（guest → 非空 user）；
  3. 迁移失败重试时未校验 `meta.import.id`，把上一次的半份数据当成本次结果；
  4. 「退出登录」被实现成「把 user 数据写回 guest」。
- **影响**：**严重**。用户数据被意外复制/混入；两个空间的物理隔离承诺失效，之后所有「隔离」断言都不可信。
- **防护**（设计 §3.3 / §3.6）：
  1. 迁移必须**用户显式确认**；未点「迁过去」时目标库必须 0 行（写入桩断言）。
  2. **本机 user 库非空时不渲染迁移入口**：根本不存在 guest → 非空 user 的路径。
  3. 目标库写入带 `meta.import.id`；不同 id 一律拒绝。
  4. 退出登录**只改身份指向**，不含任何 copy/delete 代码；用代码评审 + 单测断言「退出前后两库行数不变」。
  5. `migration.v1.from` 只允许 `'guest'`；写入其它值视为损坏并拒绝执行。
  6. UI 层：迁移按钮与登录按钮是两个独立动作，不得合并成「登录并迁移」的一键流程。
- **额外基础设施**：无。

## T20 退出登录后本地与服务端状态不一致

> 新增（编号复用自原「切换中断导致身份与库不一致」，该项随决策 F 撤销）。对应决策 D 与设计 §3.4。

- **风险**：客户端已经切到 guest 并显示「已退出登录」，但服务端 session 仍然有效（请求失败/超时/5xx），于是：
  - 用户以为已退出，实际 cookie 还能读云端备份；
  - 或本地仍是 user、服务端已吊销，用户看到「用户空间」却一直 401。
- **发生条件**：
  1. 先切本地、后异步撤销（或撤销失败被静默吞掉）；
  2. `POST /api/auth/logout` 超时/网络断开，客户端当作成功；
  3. 本地写 identity 失败（配额/隐私模式），服务端已吊销；
  4. 多标签页：一个标签退出，另一个仍显示 user。
- **影响**：高。共享设备上等同于「没退出」；或用户误判自己的登录状态。
- **防护**（设计 §3.4、§3.8 R10/R11）：
  1. 顺序固定：**先撤销（或用户显式选择「只退出本机」）→ 再写身份 → reload**。
  2. 结果三态 `revoked` / `failed` / `offline`，**分别提示**，不得用「已退出登录」概括全部。
  3. `failed`/`offline` 时**不切身份**（默认），主行动是重试；用户显式选择「只退出本机」才切，并写 `earthonline.logout.v1 {serverRevoked:false}`。
  4. guest 设置页常驻一条「上次退出未在服务器完成 [重试撤销]」；这是 guest 态唯一的 `/api/*` 例外（I4、设计 §3.4.1）。
  5. 本地写身份失败 → 保持 user 态 + 提示，不得假装已退出。
  6. 多标签：`storage` 事件 → 其它标签置只读并提示刷新。
  7. 测试：三态分支各一条；断网退出后 `identity.space` 仍为 `user`（或用户选择后为 `guest` 且 journal 存在）；journal 存在时补撤销成功即清除。
- **额外基础设施**：无。

## 1. 前端侧特有风险（不在 T1–T20 内，但必须记录）

| 风险 | 说明 | 处置 |
|---|---|---|
| 本地数据未加密 | IndexedDB 明文；同设备其它用户/恶意扩展可读 | 已知接受：本地优先产品的固有属性；共享设备建议「删除本机数据」+ 系统账户隔离 |
| XSS 可读业务数据 | 即使 token 在 HttpOnly，恶意脚本仍能读 IndexedDB 并外发 | CSP（Phase H）+ 现有 `esc()` 习惯 + 不用 `innerHTML` 渲染文案 |
| 库名可枚举 | 本地库名可被同源脚本列出 | 无实际危害；不把 userId 放进库名（用 spaceKey） |
| **常驻空间标识误导** | 标识来自缓存/默认文案，与实际生效身份不符 | 标识只读 `OLIdentity.record()`；未确认/阻断时显示「身份未确认」（设计 §7.4、I10） |

## 2. 残余风险（接受并监控）

1. **D1 是关键路径单点**：D1 故障 → 无法登录（本地数据仍可用）。
2. **邮件投递不由我们控制**：进垃圾箱、延迟、退信；缓解：提示检查垃圾箱 + 60 秒重发 + 备用驱动。
3. **会话固定/共享设备**：用户不退出就离开 → 下一个人可用其账号；缓解：绝对 90 天上限 + 「已登录设备」可见 + 敏感操作重新验证。
4. **Cloudflare 免费额度**：突发流量可能触发限流；缓解：每请求 SQL ≤ 5 条、`last_seen_at` 每小时更新一次。
5. **迁移的"用户中途关闭页面"**：状态机可恢复，但需要用户回到同一浏览器。
6. **阻断页的可用性代价**：`unknown` 只阻断不给跳过，存储长期故障的设备将无法使用应用（这是为「不掩盖旧数据」付的代价，见设计 §11 待确认项）。
7. **认领路径依赖旧库可写**：若旧库处于只读/损坏状态，认领后仍可能写不进去；缓解：阻断页 + `db-unreadable` 分型，不自动修复。
